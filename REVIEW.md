# REVIEW.md — критерии ревью

Единый чек-лист для любого пулл-реквеста: автоматического (`.github/workflows/opencode-review.yml`)
и ручного. Авторевьюер читает этот файл из базовой ветки, чтобы изменения в PR не могли
подменить критерии.

## Как читать находки

- **blocker** — мержить нельзя: нарушение домена, контракта, безопасности или падающие проверки.
- **major** — ошибка или риск, который нужно исправить до мержа.
- **minor** — улучшение, не блокирующее мерж.
- **nit** — вкусовое замечание.

Каждая находка описывается так: severity, `file:line`, пункт этого файла, в чём проблема,
что сделать. Если замечаний нет — «Замечаний нет». Нельзя выдумывать проблемы ради объёма.

## 1. Проверки и CI

- [ ] `mise run check` зелёный локально или в CI (линтеры, типы, тесты).
- [ ] `mise run workflow:lint` проходит при изменении `.github/workflows`.
- [ ] `mise run api:gen` не оставляет диффа; `api/openapi/openapi.yaml` соответствует `api/main.tsp`.
- [ ] `frontend/src/api/generated` не закоммичен.
- [ ] Новые тесты падают без изменения и проходят с ним; существующие тесты обновлены.
- [ ] E2E не подменяет ответы API.

## 2. Спецификация и поведение

- [ ] Изменение закрывает требование issue/спеки, а не соседнюю задачу.
- [ ] Нет поведения, которого не просили (scope creep).
- [ ] `docs/spec.md`, ADR или GLOSSARY обновлены, если меняются требования или термины.
- [ ] Интерфейс на русском языке.
- [ ] Для бага описано воспроизведение и оно закрыто тестом.

## 3. Домен

- [ ] Часовой пояс `Asia/Almaty`.
- [ ] Рабочие часы владельца: 09:00–13:00 и 14:00–18:00.
- [ ] Окно записи — 14 календарных дней, включая сегодняшний.
- [ ] Длительность слота равна длительности выбранного типа встречи.
- [ ] Пересечения запрещены, включая частичные и между разными типами; стык впритык разрешён.
- [ ] Ограничения соблюдаются при одновременных запросах.
- [ ] Владелец один, авторизации нет; гость заходит без регистрации.
- [ ] Заметка к брони необязательна.
- [ ] Хранение в памяти процесса; перезапуск очищает данные.

## 4. Контракт и данные

- [ ] Источник правды — `api/main.tsp`; сгенерированные файлы не правят руками.
- [ ] Изменения API обратносовместимы или явно описаны.
- [ ] Валидация на бэкенде повторяет ограничения контракта.
- [ ] Ошибки API имеют понятные коды и сообщения.
- [ ] Фронтенд ходит в API только через сгенерированный SDK.

## 5. Безопасность и секреты

- [ ] В диффе нет секретов, токенов, ключей и приватных URL.
- [ ] Пользовательский ввод не попадает в shell, SQL или HTML без обработки.
- [ ] В workflows: минимальные `permissions`, actions запинены по SHA, нет `pull_request_target`
      с недоверенным кодом, fork-PR не получают секреты.
- [ ] Новые shell-команды не дают обхода read-only ограничений.

## 6. Код и тесты

- [ ] Имена и границы модулей понятны; нет дублирования и «божественных» функций.
- [ ] Нет мёртвого кода, отладочных логов и закомментированных блоков.
- [ ] Обработка ошибок явная; исключения не проглатываются.
- [ ] Тесты проверяют поведение, а не реализацию; границы (пусто/максимум/одновременность) покрыты.
- [ ] Коммиты по Conventional Commits и логически атомарные.

## 7. Документация и эксплуатация

- [ ] README, AGENTS и docs обновлены, если меняются команды, настройки или поведение.
- [ ] В PR заполнены проверки, риск и способ отката.
- [ ] Риск описан честно: что может сломаться и как это заметить.
- [ ] Откат выполним без потери данных или с явным планом.

## Границы авторевью

Автоматический ревьюер работает только на чтение: не меняет код, ветки, метки и PR,
не запускает тесты, сборки и скрипты из PR, не одобряет и не запрашивает изменения.
Он оставляет комментарий, а решение о мерже принимает человек. Если критерий неприменим
или данных нет, ревьюер пишет «не проверено» и причину.
