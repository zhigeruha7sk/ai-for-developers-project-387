# ADR-0007: Имя гостя вводит сам гость

## Статус
Принят

## Контекст
Раньше имя гостя генерировалось случайно в `GuestContext.refresh()` и подставлялось в запись
(`guest.name || 'Гость'`). Из-за этого бронь было трудно связать с реальным человеком, а в форме
записи вообще не было поля для имени. Предыдущая спецификация («Генерация клиентов… имена на
кириллице») описывала именно генерацию, поэтому изменение затрагивает требования, а не только код.

Контракт (`api/main.tsp`, `BookingInput.guestName`) и бэкенд уже принимают непустое имя, разрыв был
только во фронтенде.

## Решение
- Имя гостя вводится вручную в форме записи на странице 3; поле пустое при открытии и не
  префиллится.
- Имя обязательно: кнопка «Продолжить» неактивна, пока имя пустое или состоит только из пробелов.
- В API отправляется введённое имя без пробелов по краям; фоллбэк «Гость» не используется.
- Случайная генерация имени удаляется. Смена аватара после успешной записи может остаться.

### Положительные следствия
- Бронь можно связать с конкретным человеком, имя видно владельцу в админке.
- Поведение совпадает с уже существующим контрактом и валидацией бэкенда.

### Отрицательные следствия
- Гостю нужно каждый раз вводить имя; автозаполнения нет.
- При пустом имени запись невозможна — это осознанное ужесточение относительно фоллбэка «Гость».

## Рассмотренные альтернативы
- **Оставить генерацию имён**: не решает задачу связи брони с человеком.
- **Префилл последнего имени из localStorage**: противоречит решению «поле пустое».
- **Разрешить фоллбэк «Гость» при пустом поле**: противоречит обязательности имени и валидации
  non-blank на бэкенде.

## Связано с
- `frontend/src/pages/Booking.tsx` — поле имени, условие активности «Продолжить», отправка имени.
- `frontend/src/context/GuestContext.tsx` — удаление генерации имени.
- `docs/spec.md` — раздел «Имя гостя».
